# Просмотровщик УЗИ: кисть и измерения (px ↔ мм)

Статус: **расширено** — линейка, кисть-заполнение с ластиком, стилизация
Annotorious. Проверки проходят, чистая геометрия покрыта прогоном (20 тестов),
в браузере не кликалось.

---

## Что сделано

### 1. Инструменты

Панель над снимком (`ViewerToolPanel`), только в режиме редактирования:

| Инструмент | id | Реализация | Назначение |
|---|---|---|---|
| Навигация | `pan` | — | перетаскивание двигает снимок (по умолчанию) |
| Контур | `polygon` | Annotorious `polygon` | обводка по точкам |
| Обводка | `freehand` | Annotorious `freehand` | векторная обводка от руки |
| Кисть | `brush` | свой canvas + `raster.ts` | закрасить область, затем «Подтвердить» |
| Линейка | `ruler` | Annotorious `line` + свой SVG-слой | измерение в мм |

Раньше инструменты жили во встроенном тулбаре `@medml/viewers`; их стало
больше, чем помещается в узкую плавающую панель, а поле масштаба и кнопки
кисти требуют полноценного ввода — поэтому панель вынесена над снимком.

### Почему не работало

Три независимых дефекта, все в `useThyroidAnnotator.ts`:

1. **`setDrawingTool` вызывался раньше `SelectorPack`.** Внутри Annotorious
   `setCurrent` ищет инструмент по identifier и сразу делает `new Tool(...)`.
   Для незарегистрированного `freehand`/`line` это `new undefined()` →
   исключение обрывало инициализацию: `annoRef.current` не присваивался,
   обработчики не вешались. Регистрация теперь идёт первой.

2. **Список инструментов передавался не туда.** Ключ `tools` в конфиге
   Annotorious selector-pack не читает — он берёт список **вторым
   аргументом**: `SelectorPack(anno, { tools: [...] })`.

3. **Рисование требовало зажатого Shift.** В OSD-плагине по умолчанию
   `hotkey = 'shift'`, а `mouseTracker.enabled = false`, поэтому обычное
   перетаскивание уходило в панорамирование. Теперь режим задаётся явно
   через `setDrawingEnabled(...)`, а панорамирование вынесено в отдельный
   инструмент «Навигация».

Плюс `tool` убран из зависимостей эффекта: раньше каждое переключение
пересоздавало инстанс Annotorious (стирая аннотации) и заново наступало
на дефект №1.

### 2. Масштаб px ↔ мм

Задаётся **вручную** полем «Масштаб, px / мм» в панели над снимком.
Прежний вариант (нарисовать эталонный отрезок → ввести его длину) убран
вместе с `useThyroidCalibration`, `CalibrationModal`, `CalibrationOverlay`.

### 2а. Линейка

Доступна только когда масштаб задан (иначе кнопка заблокирована с подсказкой).
Врач проводит отрезок, над ним появляется подпись вида `14.2 мм`, повёрнутая
вдоль линии и смещённая по нормали. Измерений на кадре может быть несколько,
у каждого крестик удаления; есть кнопка «Убрать измерения».

Отрезки рисует собственный SVG-слой (`MeasurementLayer`), а не Annotorious:
так они гарантированно не попадают в черновики контуров. Координаты хранятся
в системе изображения и пересчитываются в экранные на каждое движение
вьюпорта, поэтому держатся за снимок при зуме.

### 2б. Кисть-заполнение и ластик

Отдельный инструмент «Кисть» поверх canvas-слоя (`BrushCanvasOverlay`),
не через Annotorious:

* режимы «Добавить» / «Ластик» — это один и тот же штрих со значением 1 или 0;
* размер кисти настраивается;
* «Очистить набросок» сбрасывает маску, «Подтвердить» превращает её в полигон.

Маска — `Uint8Array` в координатах изображения. По «Подтвердить» она
проходит трассировку границы (соседи по Муру + критерий Якоба) и упрощение
(Douglas-Peucker), после чего добавляется как обычный `polygon`-аннотация —
формат совпадает с тем, что создаёт Annotorious, поэтому дальше всё идёт
существующим путём черновиков.

### 2в. Стилизация Annotorious

`viewer/viewer.scss` переопределяет дефолты плагина: хэндлы вершин увеличены
с ~5 до 7px (по мелким тяжело попасть, особенно на сенсорном экране), попапы
редактирования переведены на токены (скругления, тени, шрифты, cyan-фокус),
кнопки внутри попапа приведены к виду кнопок приложения.

### 3. Размеры узлов в миллиметрах

После задания масштаба в легенде под каждым узлом показываются габариты
(`ширина × высота`). Размер берётся как максимум по всем контурам узла —
узел может быть размечен на нескольких кадрах. Эти значения врач переносит
в форму заключения руками.

## Решения, которые стоит помнить

**Активный инструмент читается через `ref`.** Обработчики Annotorious
вешаются на инстанс один раз, поэтому в замыкании застряло бы значение с
момента подписки. То же для колбэка служебных отрезков.

**Маска кисти мутируется на месте** (`Uint8Array`), ссылка не меняется —
React сам перерисовать не может. Поэтому есть счётчик `sketchVersion`,
который двигают штрихи и очистка. Использовать его как `key` канваса
нельзя: канвас пересоздавался бы после каждого штриха.

**В `BrushCanvasOverlay` refs для пропсов не нужны.** Обработчики там —
обычные React-пропсы, они пересоздаются каждый рендер и видят актуальные
значения; попытка кэшировать их в ref ловится правилом
«Cannot access refs during render».

**Коэффициент не хранится на бэкенде** — по условию задачи он нужен только
для измерения; на сервер уходят уже готовые размеры в форме заключения.

**Если всё же понадобится сохранять коэффициент** — просто так не выйдет:

```python
# medml/serializers.py, UZIShowUpdateSerializer
details = UZIFormUpdate(required=False)
```

`UZIImage.details` — это `JSONField`, но при записи он валидируется
сериализатором с явным списком полей (`UZIForm` / `UZIFormUpdate` в
`medml/json_base/forms/UZIGroupForm.py`). **Любой необъявленный ключ DRF
молча отбрасывает.** Слияние JSONB (`F('details') || value`) сделано
корректно, так что достаточно добавить поле в форму — миграция не нужна.

## Что осталось

- [ ] **Перепроверить вживую**: навигация, контур, обводка, кисть с ластиком
      и «Подтвердить», линейка с подписями, размеры узлов в мм.
- [ ] **Масштаб живёт в памяти** — при перезагрузке вводить заново.
      Если мешает: класть в `localStorage` по id снимка.
- [ ] **Ластик не вычитает из существующих контуров** — он стирает только
      текущий набросок кисти. Вычитание из уже сохранённого полигона
      требует булевых операций над многоугольниками (Clipper и подобное).
- [ ] **Автоподстановка в форму заключения.** Сейчас врач переносит размеры
      руками. Нужен ответ эксперта: какой узел соответствует полям
      «Левая доля / Правая доля / Перешеек».
- [ ] **Кисть строит один внешний контур.** Если врач оставит два
      несвязанных мазка, в полигон уйдёт только первый найденный.
- [ ] **Точность масштаба.** Значение вводится руками; стоит подумать про
      подсказку о разумном диапазоне и предупреждение при явных опечатках.

## Проверка математики

Прогонялись отдельно, 20 проверок, все прошли:

* `measurement.ts` (8) — разбор линии, длина `3-4-5`, отсечение полигона,
  деление на ноль, перевод px→мм, середина, угол (в т.ч. отрезок справа
  налево не переворачивает текст), вырожденный отрезок.
* `raster.ts` (12) — пустая маска, квадрат (периметр 36 точек, упрощение до
  4 углов, точные границы), круг, ластик, штрих без разрывов на быстром
  движении, прямая → 2 точки, отсутствие выхода за буфер у края.

Постоянного теста в репозитории нет — тестового раннера в проекте не
настроено. Если будете добавлять, `measurement.ts` — первый кандидат:
модуль чистый и полностью детерминированный.
