# Обзор архитектуры

Клиентская платформа **medml-front** - монорепозиторий семейства диагностических приложений (УЗИ, цитология, КТ, МРТ).

## Уровни

```
apps/      → прикладные приложения (маршруты, композиция)
domains/   → общие предметные контексты (пациенты, auth, layout)
lib/       → инфраструктура и модули визуализации
configs/   → общие пресеты TS / Vite / ESLint
tools/     → скрипты проверки границ и обслуживания workspaces
build/     → Docker, Nginx, поставка статики
```

## Контуры визуализации

- **2D** (`@medml/viewers`, Annotorious) - УЗИ, цитология
- **DICOM** (`@medml/ct-mri-viewer`, Cornerstone) - КТ, МРТ

Общий каркас (авторизация, списки, UI) переиспользуется; модально-специфичный код изолирован в приложениях или пакетах `lib`.

## Рабочее место врача над снимком

Просмотр 2D-снимка разложен на три уровня - так УЗИ и цитология получают
одинаковый набор возможностей из одного кода:

| Уровень | Пакет | Что содержит |
|---------|-------|--------------|
| Страница | `@medml/study_view` (domain) | Режим фокуса, раскладка "сводка / снимок / панель" |
| Рабочее место | `@medml/viewers` → `AnnotatedStudyViewer` | Инструменты, линейка с калибровкой, кисть, легенда, состояния |
| Движок | `@medml/viewers` → `UziViewer` | OpenSeadragon: zoom/pan/rotate, кадры, слоты расширения |

Инструменты разделены по режимам: навигация, линейка и задание масштаба
доступны и при просмотре (они ничего не меняют), рисование и кисть - только
в режиме редактирования.

Разметка - тоже часть общего вьюера (`lib/viewers/src/annotations`,
Annotorious 3). Приложение с библиотекой разметки не работает, оно отдаёт
вьюеру данные и получает назад правки врача:

- `annotations` - контуры текущего кадра (`ViewerAnnotation`: id, точки,
  доменные `data`, `editable`);
- `annotationStyle` - оформление по `data` и состоянию (выделен / под курсором);
- `onAnnotationChange` - что врач нарисовал, поправил или удалил;
- `newAnnotationData` - данные для только что нарисованного контура;
- `renderAnnotationPopup` - содержимое карточки выделенного контура, к контуру
  её привязывает вьюер;
- `annotationApiRef.commitSelection()` - досохранить правку перед отправкой.

Вьюер приводит Annotorious к списку `annotations` разницей (добавить / обновить
/ убрать), а не полной заменой: у Annotorious 3 полная замена при совпадающих
id оставляет на холсте «призраков», а `clearAnnotations()` шлёт события
удаления.

Несохранённые правки обоих приложений — одна модель `useContourDrafts`
(`lib/viewers/src/annotations`): по ключу контура хранится итог — создан,
изменён или удалён. На экране всегда «сервер + черновик», своей копии разметки
у приложений нет: отмена — очистка черновика, сохранение — одна мутация, после
которой снимок перечитывается.

Доменное остаётся в приложениях, и файлы в УЗИ и цитологии названы парами:

| Роль | УЗИ (`features/uzi-view`) | Цитология (`features/cytology-view`) |
|------|---------------------------|--------------------------------------|
| Страница | `UziViewPage` | `CytologyViewPage` |
| Вьюер исследования | `viewer/UziStudyViewer` | `viewer/CytologyStudyViewer` |
| Контуры для вьюера (сервер + черновик) | `viewer/useUziContours` | `viewer/useCytologyContours` |
| Построение контуров и стиль | `viewer/uziAnnotations` | `viewer/cytologyAnnotations` |
| Карточка выделенного контура | `viewer/UziContourCard` | `viewer/CytologyContourCard` |
| Правка: режим, черновик, сохранение | `model/useUziContourEditor` | `model/useCytologyContourEditor` |
| Мутация сохранения | `saveUziContourDrafts` | `saveCytologyRevision` |

Цитология сохраняет правки новой ревизией (копия исследования, затем правки
сегментов копии) и переходит на неё. Своего Redux-стора у страницы цитологии
нет: состояние для панели справа — `model/CytologyViewContext`. Модалки
(`ModalContext.open`) рисуются в корне приложения, вне этого контекста, —
данные и колбэки им передаются пропсами.
